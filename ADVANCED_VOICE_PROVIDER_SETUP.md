## 1. Executive Summary & Security Doctrine

The AI Business Secretary & Accountant is designed around a **Security-First Financial Architecture**.

### The Non-Negotiable Rules of Financial AI Security:
1. **Zero Secret Keys in Frontend Code:** Never expose API keys (e.g., `GEMINI_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) in client-side code, Git commits, or `VITE_*` browser environment variables. Any key bundled in frontend JavaScript can be trivially extracted by end users via browser DevTools.
2. **Zero Financial Hallucination:** Authoritative financial totals, currency balances, exchange rates, and inventory valuations must **never** be calculated independently by an LLM. All authoritative figures must be computed by deterministic application business logic.
3. **Zero Unauthorized Cloud Database Writes:** Financial actions must pass through the approval draft pipeline and receive explicit human authorization before posting to the ledger.
4. **Honest System Status Disclosure:** The system explicitly labels when responses are generated by the local deterministic engine vs an external LLM.

## 2. Current Architecture: Deterministic Local Provider (Active Default)

In the current demonstration build, the assistant runs on the **`DeterministicLocalProviderAdapter`**:
- **Location:** `src/ai/voice/providerAdapter.ts`
- **Execution:** 100% in-browser JavaScript/TypeScript execution.
- **Data Access:** Directly queries the shared in-memory `DemoDataset` (persisted in `localStorage` under `absa.demo.state.v1`).
- **Cost:** \$0.00 / month.
- **Latency:** Instantaneous sub-millisecond calculation (with a simulated 350ms natural conversational pause).
- **Privacy:** 100% air-gapped. Zero confidential accounting or trade data leaves the client's device.
- **UI Label:** `"Simulated assistant"` · `"Local Demo Engine (Simulated)"`.

## 3. Enterprise Production Setup: Stateless AI Proxy Architecture

When transitioning from the demonstration environment to a full enterprise deployment, an external LLM (such as Google Gemini 1.5 Pro, Anthropic Claude 3.5 Sonnet, or OpenAI GPT-4o) should be integrated via a **Stateless Secure Backend Proxy**.

```
+---------------------------------------------------------------------------------+
|                       CLIENT BROWSER (Vite React App)                           |
|  - Speech-to-Text captures audio & transcribes to text                          |
|  - ConversationManager resolves multi-turn context slots                        |
|  - ExternalProxyProviderAdapter dispatches sanitized payload                    |
+---------------------------------------------------------------------------------+
                                       |
                   HTTPS POST /api/ai/chat (Zero API Keys)
                                       v
+---------------------------------------------------------------------------------+
|                    SECURE BACKEND SERVER (Node.js / FastAPI)                    |
|  - Validates user authentication & session token                                |
|  - Stores server-side secret: `GEMINI_API_KEY` (Never sent to browser)          |
|  - Injects audited business tools definitions (Function Calling)                |
|  - Calls LLM API over TLS with minimal prompt context                           |
|  - Formats response and returns sanitized JSON to client                        |
+---------------------------------------------------------------------------------+
                                       |
                   Encrypted API Call (Server-to-Server)
                                       v
+---------------------------------------------------------------------------------+
|               ENTERPRISE AI PROVIDER (Google Vertex AI / Gemini)               |
+---------------------------------------------------------------------------------+
```

## 4. Step-by-Step Backend Proxy Implementation Guide

### Step 1: Deploy a Minimal Stateless Proxy Endpoint
Create an endpoint (e.g. in Express, Next.js, or Vercel Serverless Functions) at `/api/ai/chat`:

```javascript
// Example Vercel / Express Serverless Handler (/api/ai/chat.js)
import { GoogleGenerativeAI } from '@google/generative-ai';

// API Key resides exclusively in server environment variables
const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);

export default async function handler(req, res) {
  if (req.method !== 'POST') {
    return res.status(405).json({ error: 'Method not allowed' });
  }

  const { query, slots, language } = req.body;

  try {
    const model = genAI.getGenerativeModel({
      model: 'gemini-1.5-flash',
      systemInstruction: `You are an AI Business Secretary for ABC Trading Company.
      Language mode: ${language}.
      Current conversation slots: ${JSON.stringify(slots)}.
      Never invent financial numbers. If asking about balances or transactions, use approved tools.`,
    });

    const chat = model.startChat();
    const result = await chat.sendMessage(query);
    const response = await result.response;

    return res.status(200).json({
      intent: 'assistant.response',
      intentLabel: 'AI Secretary · Natural Language',
      module: 'Executive',
      language: language === 'en' ? 'en' : 'roman-urdu',
      text: response.text(),
    });
  } catch (error) {
    console.error('AI Proxy Error:', error);
    // Return 500 so frontend gracefully falls back to deterministic local engine
    return res.status(500).json({ error: 'AI proxy error' });
  }
}
```

### Step 2: Configure Server Environment Secrets
In your deployment environment (Vercel, Railway, AWS, or Cloud Run):

```bash
# Add on your server or Vercel dashboard:
GEMINI_API_KEY="AIzaSyYourSecretServerSideKeyHere"
# or for OpenAI:
OPENAI_API_KEY="sk-proj-YourSecretKeyHere"
```

> [!CAUTION]
> **DO NOT** prefix the key with `VITE_` (e.g., `VITE_GEMINI_API_KEY`). In Vite, any variable starting with `VITE_` is automatically compiled directly into public client JavaScript bundles!

---

### Step 3: Enable External Proxy in `src/ai/voice/voiceAssistantService.ts`
To switch from the local deterministic adapter to the external proxy adapter:

```typescript
// In src/ai/voice/voiceAssistantService.ts:
import { ExternalProxyProviderAdapter } from './providerAdapter';

// Replace:
// this.providerAdapter = new DeterministicLocalProviderAdapter();
// With:
this.providerAdapter = new ExternalProxyProviderAdapter('/api/ai/chat');
```

## 5. Automatic Graceful Fallback Guarantees

The `ExternalProxyProviderAdapter` is designed with an automatic safety fallback:
1. If `/api/ai/chat` is not reachable, network drops, or the server returns an error, the service **does not crash or show an empty response**.
2. It immediately routes the query to the **`DeterministicLocalProviderAdapter`**, answering the user's question accurately from the shared demo dataset.
3. The user experience remains seamless and unbroken even during cloud API outages.
