## 1. Executive Summary & Security Doctrine

The AI Business Secretary & Accountant is designed around a **Security-First Financial Architecture**.

### The Non-Negotiable Rules of Financial AI Security:
1. **Zero Secret Keys in Frontend Code:** Never expose API keys (e.g., `GEMINI_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) in client-side code, Git commits, or `VITE_*` browser environment variables. Any key bundled in frontend JavaScript can be trivially extracted by end users via browser DevTools.
2. **Zero Financial Hallucination:** Authoritative financial totals, currency balances, exchange rates, and inventory valuations must **never** be calculated independently by an LLM. All authoritative figures must be computed by deterministic application business logic.
3. **Zero Unauthorized Cloud Database Writes:** Financial actions must pass through the approval draft pipeline and receive explicit human authorization before posting to the ledger.
4. **Honest System Status Disclosure:** The system explicitly labels when responses are generated by the local deterministic engine vs an external LLM, and provides accurate status for browser speech recognition services.

## 2. Speech Recognition (STT): Browser Cloud Dependency & Root Cause of Network Errors

### Why the Chrome Web Speech API Throws `network` Errors

In Google Chrome and Chromium-based browsers, the `webkitSpeechRecognition` implementation is **not an on-device speech engine**.

```
+---------------------------------------------------------------------------------------+
|                                    USER'S BROWSER (Chrome)                            |
|                                                                                       |
|   1. User clicks Mic                                                                  |
|   2. Browser captures raw PCM audio from microphone                                   |
|   3. Audio chunks streamed over TLS/WSS to Google Cloud Speech Servers                |
+---------------------------------------------------------------------------------------+
                                        |
                 Streaming Audio WebSocket to Google:
                 https://www.google.com/speech-api/...
                                        v
+---------------------------------------------------------------------------------------+
|                           GOOGLE PROPRIETARY SPEECH ENDPOINTS                         |
|   - Transcribes audio stream into text tokens                                         |
|   - Sends incremental interim and final transcripts back to Chrome                    |
+---------------------------------------------------------------------------------------+
```

### Root Cause of the `network` Error:
When Chrome cannot complete the connection to Google's cloud speech endpoints, it fires an `onerror` event with `event.error === 'network'`. This occurs when:
1. **Firewalls & Corporate Filters:** Corporate or institutional networks frequently block raw audio streaming to Google's speech endpoints.
2. **DNS & Regional ISP Blocks:** In regions where Google APIs experience packet loss, throttling, or DNS interception, the WebSocket fails.
3. **VPN Interference:** Many VPN configurations interfere with WebSockets or reject UDP/streaming connections.
4. **Transient Outages & Rate Limits:** Google's public speech endpoints occasionally throttle unauthenticated browser requests.

### Client-Side Resilience in This Application:
Instead of blaming the user's internet connection, our application implements an **Honest, Non-Blocking Fallback**:
- Surfaces the honest message: *"Voice recognition service is unavailable. Please check your connection or use text input."*
- Immediately halts audio capture and frees MediaStream tracks so the microphone hardware is not held hostage.
- Cleans up AudioContext and resets internal state to `error` (preventing an indefinite "Listening…" state).
- Preserves whatever partial speech was captured so far directly into the chat input.
- Automatically focuses the chat text area so the user can continue typing seamlessly.
- Provides a manual **"Retry Voice"** button and **"Type Instead"** action without creating infinite retry loops.

## 3. Enterprise Production Architecture: Dedicated Backend STT Proxy

To completely eliminate dependency on Google's unauthenticated browser speech service in production, implement a **Stateless Backend Speech-to-Text Proxy** using OpenAI Whisper or Google Cloud Speech-to-Text v2.

```
+---------------------------------------------------------------------------------+
|                       CLIENT BROWSER (Vite React App)                           |
|  - MediaRecorder captures audio blob (WebM / Opus)                              |
|  - Zero API keys in frontend code                                               |
|  - POST /api/ai/transcribe (Audio blob multipart/form-data)                     |
+---------------------------------------------------------------------------------+
                                       |
                   HTTPS POST /api/ai/transcribe (Zero API Keys)
                                       v
+---------------------------------------------------------------------------------+
|                    SECURE BACKEND SERVER (Node.js / Express / Vercel)           |
|  - Validates user JWT session                                                   |
|  - Holds server-side secret: `OPENAI_API_KEY` or GCP Service Account JSON        |
|  - Streams audio to Whisper API or Google Cloud Speech-to-Text v2               |
|  - Returns clean transcript text to client browser                              |
+---------------------------------------------------------------------------------+
                                       |
                    Encrypted Server-to-Server API Call
                                       v
+---------------------------------------------------------------------------------+
|               ENTERPRISE SPEECH PROVIDER (Whisper / GCP STT)                    |
+---------------------------------------------------------------------------------+
```

### Production STT Endpoint Implementation (`/api/ai/transcribe.js`):

```javascript
// Example Vercel / Express Serverless Handler (/api/ai/transcribe.js)
import OpenAI from 'openai';
import formidable from 'formidable';
import fs from 'fs';

// Server-side secret — never exposed to client browser
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

export const config = {
  api: {
    bodyParser: false, // Handle raw multipart audio streams
  },
};

export default async function handler(req, res) {
  if (req.method !== 'POST') {
    return res.status(405).json({ error: 'Method not allowed' });
  }

  try {
    const form = formidable({ keepExtensions: true });
    const [fields, files] = await form.parse(req);
    const audioFile = files.audio?.[0];

    if (!audioFile) {
      return res.status(400).json({ error: 'No audio file provided' });
    }

    const language = fields.language?.[0] || 'ur'; // ur (Urdu) or en (English)

    const transcription = await openai.audio.transcriptions.create({
      file: fs.createReadStream(audioFile.filepath),
      model: 'whisper-1',
      language: language === 'en' ? 'en' : 'ur',
      prompt: 'Urdu and English business conversation, accounting, sales, ledger, payments.',
    });

    return res.status(200).json({
      text: transcription.text,
      language,
    });
  } catch (error) {
    console.error('STT Proxy Error:', error);
    return res.status(500).json({ error: 'Transcription failed' });
  }
}
```

## 4. Current Architecture: Deterministic Local Provider (Active Default)

In the current demonstration build, the assistant runs on the **`DeterministicLocalProviderAdapter`**:
- **Location:** `src/ai/voice/providerAdapter.ts`
- **Execution:** 100% in-browser JavaScript/TypeScript execution.
- **Data Access:** Directly queries the shared in-memory `DemoDataset` (persisted in `localStorage` under `absa.demo.state.v1`).
- **Cost:** \$0.00 / month.
- **Latency:** Instantaneous sub-millisecond calculation (with a natural simulated conversational delay).
- **Privacy:** 100% air-gapped. Zero confidential accounting or trade data leaves the client's device.
- **UI Label:** `"Simulated assistant"` · `"Local Demo Engine (Simulated)"`.

## 5. Enterprise Production Setup: Stateless AI Proxy Architecture (Chat & Reasoning)

When transitioning from the demonstration environment to a full enterprise deployment, an external LLM (such as Google Gemini 1.5 Pro, Anthropic Claude 3.5 Sonnet, or OpenAI GPT-4o) should be integrated via a **Stateless Secure Backend Proxy**.

```
+---------------------------------------------------------------------------------+
|                       CLIENT BROWSER (Vite React App)                           |
|  - Speech-to-Text captures audio & transcribes to text                          |
|  - ConversationManager resolves multi-turn context slots                        |
|  - ExternalProxyProviderAdapter dispatches sanitized payload                    |
+---------------------------------------------------------------------------------+
                                       |
                   HTTPS POST /api/ai/chat (Zero API Keys)
                                       v
+---------------------------------------------------------------------------------+
|                    SECURE BACKEND SERVER (Node.js / FastAPI)                    |
|  - Validates user authentication & session token                                |
|  - Stores server-side secret: `GEMINI_API_KEY` (Never sent to browser)          |
|  - Injects audited business tools definitions (Function Calling)                |
|  - Calls LLM API over TLS with minimal prompt context                           |
|  - Formats response and returns sanitized JSON to client                        |
+---------------------------------------------------------------------------------+
                                       |
                   Encrypted API Call (Server-to-Server)
                                       v
+---------------------------------------------------------------------------------+
|               ENTERPRISE AI PROVIDER (Google Vertex AI / Gemini)               |
+---------------------------------------------------------------------------------+
```

### Chat Endpoint Implementation (`/api/ai/chat.js`):

```javascript
// Example Vercel / Express Serverless Handler (/api/ai/chat.js)
import { GoogleGenerativeAI } from '@google/generative-ai';

// API Key resides exclusively in server environment variables
const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);

export default async function handler(req, res) {
  if (req.method !== 'POST') {
    return res.status(405).json({ error: 'Method not allowed' });
  }

  const { query, slots, language } = req.body;

  try {
    const model = genAI.getGenerativeModel({
      model: 'gemini-1.5-flash',
      systemInstruction: `You are an AI Business Secretary for ABC Trading Company.
      Language mode: ${language}.
      Current conversation slots: ${JSON.stringify(slots)}.
      Never invent financial numbers. If asking about balances or transactions, use approved tools.`,
    });

    const chat = model.startChat();
    const result = await chat.sendMessage(query);
    const response = await result.response;

    return res.status(200).json({
      intent: 'assistant.response',
      intentLabel: 'AI Secretary · Natural Language',
      module: 'Executive',
      language: language === 'en' ? 'en' : 'roman-urdu',
      text: response.text(),
    });
  } catch (error) {
    console.error('AI Proxy Error:', error);
    // Return 500 so frontend gracefully falls back to deterministic local engine
    return res.status(500).json({ error: 'AI proxy error' });
  }
}
```

## 6. Automatic Graceful Fallback Guarantees

The `ExternalProxyProviderAdapter` is designed with an automatic safety fallback:
1. If `/api/ai/chat` is not reachable, network drops, or the server returns an error, the service **does not crash or show an empty response**.
2. It immediately routes the query to the **`DeterministicLocalProviderAdapter`**, answering the user's question accurately from the shared demo dataset.
3. The user experience remains seamless and unbroken even during cloud API outages.
